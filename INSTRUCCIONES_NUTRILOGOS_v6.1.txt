CÓMO USAR ESTA GUÍA
───────────────────
- Vive en las instrucciones del proyecto NutriLogos. Cada chat de cliente tiene su
  CLIENTE.md con los datos de esa persona. El plan sale de esta guía + el CLIENTE.md.
- Es autocontenida: la Sección 9 lleva la plantilla completa (HTML, CSS y JavaScript).
- REGLA DE ORO: la plantilla se copia TAL CUAL. Solo se rellenan los marcadores {{...}} y
  los datos (los arrays days, shopCategories y recetas). Nunca se reescribe ni se
  "mejora" el CSS ni el JavaScript, y nunca se cambian colores, tamaños ni estructura.
- Lo que no está en esta guía no es estándar. Lo opcional solo se añade si el
  profesional lo pide expresamente, nunca por defecto.

## 1. PRINCIPIOS

1. UN solo HTML por cliente, autónomo (lleva su CSS y su JS dentro). Para actualizar un
   plan se edita ese mismo archivo: nunca se duplica ni se crea una copia con sufijo.
   El historial lo conserva GitHub.
2. Español y segunda persona ("tu recuperación", "tus gustos").
3. Mismo aspecto que la app de clientes de NutriLogos, que muestra el plan dentro de un
   <iframe>. Todos los planes se ven igual, con independencia del cliente.
4. Los datos del cliente NO van en el HTML: la descripción en píldoras y el perfil
   completo (métricas, somatotipo, antropometría, bioimpedancia, fuerza y equilibrio)
   viven en el CLIENTE.md de cada chat (estructura en el Anexo B).
5. Evidencia científica: cuanto más vegetal e integral sea la alimentación, mejor.

## 2. NOMBRE DEL ARCHIVO Y MODOS DE TRABAJO

Modo chat de proyecto (el habitual)
- El chat entrega `nombreapellido.html`: nombre y apellido del cliente en minúsculas,
  sin espacios ni tildes (ej.: "María López" → `marialopez.html`).
- Los datos del cliente están en `CLIENTE.md`.
- El profesional descarga el archivo y lo sube a GitHub como `index.html` para que se
  pueda leer y publicar.

Modo repo por cliente (cuando el plan se gestiona desde Claude Code)
- Repo `nombreapellido` con `index.html`, `CLAUDE.md` (equivale al CLIENTE.md), `Logo.png`
  y `_headers.txt` (cabeceras de caché). GitHub Pages publica `index.html` desde main.
- Las reglas del plan (Secciones 3 a 8) son las mismas en los dos modos.

## 3. ESTRUCTURA DEL PLAN (orden fijo)

1. h1 "Planificación Nutricional — [NOMBRE]" + subtítulo (objetivo · estructura · meta)
2. Objetivo
3. Impresiones del profesional
4. Menú semanal de un vistazo (#printArea): tabla generada desde el JS + leyenda
5. Menú desarrollado por días (pestañas) + leyenda
6. Lista de compra semanal (pestañas, ítems tachables)
7. Recetas (acordeón)
8. SOLO SI SE PIDEN: Suplementación (tras la lista de compra) y Sección personalizada
   (tras Recetas). Ver Sección 7.

Cada sección: <div style="margin-top:2.5rem;"> + <div class="section-label">.
Sin <hr>, sin border-top. El único borde inferior es el del .section-label.

## 5. DATOS (los arrays JS de la plantilla)

### 5.1 days[]  (7 días)
```
{ short:"Lun", full:"Lunes",
  sport:"🏃 Rodaje",              // emoji + tipo de sesión
  sportClass:"run",               // run | fuerza | crossfit | rest
  sportBanner:"Descripción de la sesión y cómo afecta a las comidas",
  suppl:null,                     // null o texto con \n (recordatorio de suplementación)
  libre:false,                    // true → banner de cena libre
  meals:[ { type:"C", time:"14:00", name:"Comida", tags:[], recetas:[0],
            desc:"Línea 1\nLínea 2", short:"Resumen corto",
            note:"adaptación o consejo", libre:false } ],
  batchCooking:null }             // null o { title, items[], note }
```
- `short` del día: 2-3 letras ("Lun"). Si hay cena libre, "Sáb ★".
- `sportBanner`: kcal o macros solo si aportan algo a ese cliente; decisión del
  profesional.
- Tipos de comida: D Desayuno · A Almuerzo (media mañana) · C Comida (mediodía) ·
  Me Merienda · Ce Cena. Comidas por defecto: D, A, C, Me, Ce. Se quitan las que el
  cliente no hace. No confundir nunca A con C.
- `desc`: cada `\n` crea una pill de ingrediente.
- `short` de la comida: resumen de 2-4 palabras que sale en la tabla semanal.
- `tags`: [] | ["extra"] ("Hacer cantidad extra") | ["batch"] ("Usar del batch cooking").
- `recetas`: opcional; índices de `recetas[]` si la comida tiene receta abajo (5.4).
- `libre:true` en una comida la pinta como "Libre".
- `suppl` y `batchCooking` solo se usan si se pide suplementación o batch cooking.

### 5.2 Tabla semanal
No se escribe a mano: `buildSummary()` la genera desde `days[]` con el `short` de cada
comida. Solo salen las filas de las comidas que el cliente tiene en algún día; el resto
muestra "—". La leyenda de la tabla y la del menú por días las genera `buildLegends()`.
Al cambiar una comida hay que actualizar `short`, `desc`, `note` Y la lista de compra.

### 5.3 shopCategories[]
Cuatro categorías fijas, con sus emojis: 🫘 Proteínas (cat-prot) · 🌾 Carbohidratos
(cat-carb) · 🥑 Grasas (cat-fat) · 🧄 Extras (cat-extra). Cada ítem: { name, qty }.

### 5.4 recetas[] e indicador de receta
`{ emoji, nombre, corto, tiempo, raciones, utensilios, ingredientes[], pasos[], tip }`.
- Si una comida tiene receta, lleva `recetas:[i]` y `render()` pinta encima del título la
  etiqueta "📖 Receta abajo: [corto]"; al pulsarla, `verReceta(i)` abre la receta y baja
  hasta ella. `corto` es el nombre abreviado; si es una opción, termina en "(opción)".
- La plantilla trae una receta de relleno ("Receta por definir") enlazada al Lunes: se
  sustituye. Si el cliente no tiene recetas, se quitan el array, el bloque HTML de
  Recetas y todos los `recetas:[...]`.

### 5.5 Reglas de JavaScript
- UN único <script> al final del <body>.
- #shopTabs y #shopView van en el body ANTES del <script>.
- Las funciones no se modifican por cliente; solo cambian los arrays.
- Llamadas finales, en este orden: buildTabs(); render(); buildSummary(); buildLegends();
  buildShopTabs(); renderShop(); buildRecetas();

## 6. ESTILO EDITORIAL

1. Tono: cercano, positivo y directo, en segunda persona. Frases cortas.
2. Cantidades: gramos con su equivalente en medidas caseras (vasos, tazas, cucharadas,
   cucharaditas, puñados, rebanadas, piezas). Pesos en crudo salvo que se indique.
3. Fruta: en piezas, sin pesarla, y cuantas más, mejor (fibra, vitaminas y minerales: a
   más fruta entera en la planificación, mejor para la salud). En la tabla semanal, las
   comidas que la llevan terminan su `short` con "+ fruta".
4. `name` es el nombre del plato; `desc`, una pill por ingrediente con su cantidad.
5. `note` empieza en minúscula (la plantilla antepone "Adaptación:"), con una o dos
   frases prácticas. No repetir lo que ya dice `desc`.
6. Opciones puntuales: una línea "Opción: … (ver receta)" al final de `desc` y la receta
   con `corto` terminado en "(opción)".
7. Impresiones: entre 4 y 6 puntos, cada uno con título en negrita y una o dos frases.
   Usar el semáforo (verde, azul, ámbar, coral) con su significado fijo.
8. No mencionar a terceros (familiares u otras personas) en el plan, salvo que el
   profesional lo pida: se habla de la comida, no de quién la prepara.
9. Objetivo: texto desarrollado, con la meta del primer periodo si la hay.

## 7. BLOQUES OPCIONALES (solo si el profesional los pide)

### 7.1 Suplementación (tras la lista de compra)
```html
<div style="margin-top:2.5rem;">
  <div class="section-label">Suplementación recomendada</div>
  <div class="pn-supl-block">
    <div class="pn-supl-item"><div class="pn-supl-dot"></div>
      <div><strong>[SUPLEMENTO]</strong> — [DOSIS, FRECUENCIA Y JUSTIFICACIÓN]</div></div>
  </div>
</div>
```

### 7.2 Batch cooking
Campo `batchCooking: { title, items[], note }` en el día correspondiente (normalmente el
domingo) y tag `["batch"]` en las comidas que usan lo cocinado.

### 7.3 Sección personalizada (tras Recetas)
Solo bajo petición expresa. Mismo patrón de sección (margin-top:2.5rem + section-label
descriptivo) y tarjetas con borde var(--bdm) y radio 12px. Iconos de estado:
  ✅ completado         → fondo var(--t50)       borde var(--t100)
  🔵 próximo o en curso → fondo var(--gold-50)   borde var(--pill-au)
  ⬜ pendiente          → fondo var(--g100)      borde var(--g200)
  ❌ no logrado (con criterio) → fondo #fdf0f0   borde #f4b8b8
Cada ítem: <div style="display:flex;align-items:center;gap:10px;padding:6px 10px;
background:[fondo];border:1px solid [borde];border-radius:8px;"> icono (18px) + título
(13px, 500) + detalle (12px, var(--g400)).

    utensilios: "🔥 —",
    ingredientes: [ "Por definir tras la consulta" ],
    pasos: [ "Las recetas se añadirán una vez definido el menú y tus gustos." ],
    tip: "💡 Aquí irán recetas sencillas adaptadas a tu plan."
  }
];
 
function badgeClass(type, libre) {
  if (libre) return "badge-libre";
  const map = { D:"badge-d", A:"badge-a", Me:"badge-me", C:"badge-c", Ce:"badge-ce" };
  return map[type] || "badge-c";
}
function badgeLabel(type, libre) {
  if (libre) return "Libre";
  const map = { D:"Desayuno", A:"Almuerzo", Me:"Merienda", C:"Comida", Ce:"Cena" };
  return map[type] || type;
}
 
let current = 0;
 
function render() {
  const d = days[current];
  let html = `<div style="font-size:18px;font-weight:500;color:var(--g900);margin-bottom:8px">${d.full}</div>`;
  html += `<div class="pn-sport-banner ${d.sportClass}">${d.sport} — ${d.sportBanner}</div>`;
  if (d.libre) html += `<div class="pn-libre-banner">La cena de este día está reservada como comida libre. El resto del día sigue el plan habitual.</div>`;
  if (d.suppl) html += `<div class="pn-supp-banner">` + d.suppl.replace(/\n/g,"<br>") + `</div>`;
  if (d.batchCooking) {
    const bc = d.batchCooking;
    const items = bc.items.map(i => `<li>${i}</li>`).join("");
    html += `<div class="pn-batch-section"><h3>${bc.title}</h3><ul>${items}</ul><div class="bc-note">⏱ ${bc.note}</div></div>`;
  }
  html += `<div class="pn-meals">`;
  d.meals.forEach(m => {
    const bc = badgeClass(m.type, m.libre);
    const bl = badgeLabel(m.type, m.libre);
    let tagsHtml = "";
    if (m.tags && m.tags.includes("extra")) tagsHtml += `<span class="pn-extra-tag">🥡 Hacer cantidad extra</span> `;
    if (m.tags && m.tags.includes("batch")) tagsHtml += `<span class="pn-batch-tag">♻️ Usar del batch cooking</span> `;
    if (m.recetas && m.recetas.length) m.recetas.forEach(i => { tagsHtml += `<a href="#recetasList" class="pn-receta-tag" onclick="verReceta(${i});return false;">📖 Receta abajo: ${recetas[i].corto}</a> `; });
    const rawParts = m.desc.split(/\n/).map(s => s.trim()).filter(s => s.length > 0);
    let ingsHtml = rawParts.map(part => `<span class="pn-ing">${part}</span>`).join("");
    html += `
      <div class="pn-card">
        <div class="pn-meal-header">
          <span class="pn-badge ${bc}">${bl}</span>
          <span class="pn-time">${m.time}</span>
        </div>
        ${tagsHtml ? `<div style="margin-bottom:6px">${tagsHtml}</div>` : ""}
        <div class="pn-name">${m.name}</div>
        <div class="pn-ing-list">${ingsHtml}</div>
        <div class="pn-note">Adaptación: ${m.note}</div>
      </div>`;
  });
  html += `</div>`;
  document.getElementById("dayView").innerHTML = html;
}
 
function buildTabs() {
  const container = document.getElementById("dayTabs");
  days.forEach((d, i) => {
    const btn = document.createElement("button");
    btn.className = "pn-day-btn" + (i === 0 ? " active" : "");
    btn.textContent = d.short;
    btn.onclick = () => {
      document.querySelectorAll(".pn-day-btn").forEach(b => b.classList.remove("active"));
      btn.classList.add("active");
      current = i;
      render();
    };
    container.appendChild(btn);
  });
}
 
function buildSummary() {
  const allRows = [
    { type:"D", bg:"#f9fcf5" },
    { type:"A", bg:"#f0f9f6" },
    { type:"C", bg:"#f3fdf8" },
    { type:"Me", bg:"#f5f3ff" },
    { type:"Ce", bg:"#fdf8ff" }
  ];
  // Solo se muestran las filas de las comidas que el cliente tiene en algún día
  const rows = allRows.filter(r => days.some(d => d.meals.some(m => m.type === r.type)));
  const tbody = document.getElementById("summaryBody");
  let html = "";
  rows.forEach(row => {
    html += `<tr>`;
    html += `<td style="background:#f7f7f7;padding:8px 6px;border-right:2px solid #e0e0e0;border-bottom:1px solid #eee;text-align:center;vertical-align:middle;"><span class="pn-badge badge-${row.type.toLowerCase()}" style="display:inline-block;">${row.type}</span></td>`;
    days.forEach(d => {
      const meal = d.meals.find(m => m.type === row.type);
      let cellHtml, cellBg = row.bg;
      if (!meal) {
        cellHtml = `<span style="color:#aaa;font-style:italic;">—</span>`;
      } else if (meal.libre) {
        cellHtml = `Libre`;
        cellBg = "#fbeaf0";
      } else {
        cellHtml = meal.short || meal.name;
      }
      const styleLibre = meal && meal.libre ? "color:#72243E;font-style:italic;" : "color:#333;";
      html += `<td style="background:${cellBg};padding:8px 10px;border-right:1px solid #eee;border-bottom:1px solid #eee;text-align:center;${styleLibre}line-height:1.4;">${cellHtml}</td>`;
    });
    html += `</tr>`;
  });
  tbody.innerHTML = html;
}

function buildLegends() {
  const names = { D:"Desayuno", A:"Almuerzo", C:"Comida", Me:"Merienda", Ce:"Cena" };
  const present = Object.keys(names).filter(t => days.some(d => d.meals.some(m => m.type === t)));
  const items = present.map(t => `<span class="pn-legend-item"><span class="pn-badge badge-${t.toLowerCase()}">${t}</span> ${names[t]}</span>`).join("");
  [["tableLegend", "Leyenda:"], ["dayLegend", "Comidas:"]].forEach(([id, label]) => {
    const el = document.getElementById(id);
    if (el) el.innerHTML = `<span style="font-size:12px;color:var(--g400);margin-right:4px;">${label}</span>` + items;
  });
}

let shopCurrent = 0;

    </div>`;

function buildShopTabs() {

}
 
function buildRecetas() {
  if (typeof recetas === "undefined" || !recetas.length) return;
  const container = document.getElementById("recetasList");
  if (!container) return;
  recetas.forEach((r, i) => {
    const div = document.createElement("div");
    div.className = "pn-receta";
    div.innerHTML = `
      <div class="pn-receta-header" onclick="toggleReceta(${i})">
        <div class="pn-receta-title">${r.emoji} ${r.nombre}</div>
        <span class="pn-receta-arrow">▸</span>
      </div>
      <div class="pn-receta-body">
        <div class="pn-receta-meta">
          <span class="pn-receta-meta-pill">${r.tiempo}</span>
          <span class="pn-receta-meta-pill">${r.raciones}</span>
          <span class="pn-receta-meta-pill">${r.utensilios}</span>
        </div>
        <div class="pn-receta-section">🧺 Ingredientes</div>
        <div class="pn-receta-ings">${r.ingredientes.map(ing => `<span class="pn-receta-ing">${ing}</span>`).join("")}</div>
        <div class="pn-receta-section">👨‍🍳 Elaboración</div>
        <ol class="pn-receta-steps">${r.pasos.map((p,n) => `<li class="pn-receta-step"><span class="pn-receta-step-num">${n+1}</span><span>${p}</span></li>`).join("")}</ol>
        <div class="pn-receta-tip">${r.tip}</div>
      </div>`;
    container.appendChild(div);
  });
}
 
function verReceta(i) {
  const cards = document.querySelectorAll(".pn-receta");
  if (!cards[i]) return;
  cards[i].classList.add("open");
  const reduce = window.matchMedia("(prefers-reduced-motion: reduce)").matches;
  cards[i].scrollIntoView({ behavior: reduce ? "auto" : "smooth", block: "start" });
}

function toggleReceta(i) {
  const cards = document.querySelectorAll(".pn-receta");
  cards[i].classList.toggle("open");
}
 
buildTabs();
render();
buildSummary();
buildLegends();
buildShopTabs();
renderShop();

</script>
</body>

## ANEXO B. ESTRUCTURA DEL CLIENTE.md

Es la ficha del cliente dentro de su chat. Todo lo que antes iba en el HTML (descripción
y perfil) vive aquí.

1. DESCRIPCIÓN (cinco campos): Perfil (sexo · edad · talla · peso) · Contexto (profesión
   o situación vital) · Objetivo · Hábitos (tabaco · alcohol · sueño) · Aversiones o
   exclusiones.
2. VALORACIÓN (fecha y profesional)
   - Peso, IMC, talla y envergadura (relativa), tipo corporal.
   - % de masa grasa: Durnin-Womersley como referencia principal; Yuhasz como secundaria.
   - Pliegues (tríceps, subescapular, bíceps, cresta ilíaca, supraespinal, abdominal,
     muslo, pierna), Σ6 y Σ8.
   - Perímetros (cintura, cadera, brazo relajado y contraído, muslo, pierna) y ratio
     cintura/cadera.
   - Masa muscular, masa libre de grasa, tejido adiposo (Ross y Kerr), TMB.
   - Somatotipo (Carter-Heath): valoración actual, previa y grupo de referencia (ISAK).
   - Bioimpedancia: dato complementario, que se usa con cautela (agua, masa ósea, masa
     grasa, músculo esquelético, grasa visceral, equilibrio y fuerza).
3. CÁLCULO ENERGÉTICO: BMR, gasto total (TDEE), calorías objetivo, macros y masa libre
   de grasa usada en el cálculo.
4. ACTIVIDAD Y HORARIOS: entrenamientos, comidas y quién o cómo las prepara.
5. CRITERIOS NUTRICIONALES decididos para este cliente.
6. PENDIENTES y notas de seguimiento.
