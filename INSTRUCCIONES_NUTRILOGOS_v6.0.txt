- Un repositorio por cliente. Nombre: nombre y apellido en minúsculas y sin espacios

- Idioma: español. El plan se redacta en SEGUNDA PERSONA ("tu recuperación", "tus gustos").

## 2. ESTRUCTURA DE index.html (orden fijo)

1. h1 "Planificación Nutricional — [NOMBRE]" + subtítulo (objetivo · estructura · meta)
2. Objetivo
3. Impresiones del profesional
4. Menú semanal de un vistazo (#printArea, tabla generada desde el JS)
5. Menú desarrollado por días (pestañas)
6. Lista de compra semanal (pestañas, ítems tachables)
7. Recetas (acordeón)
8. OPCIONALES (solo si el cliente los necesita): Suplementación (tras la lista de
   compra) y Sección personalizada (tras Recetas). Ver Sección 7.

Cada sección: <div style="margin-top:2.5rem;"> + <div class="section-label">.
Sin <hr>, sin border-top. El único borde inferior es el del .section-label.

FUERA del HTML (la app ya lo muestra, o va al perfil máster de CLAUDE.md):
descripción del cliente, perfil con métricas (antropometría, bioimpedancia,
somatotipo), próxima revisión y botones de PDF.

## 4. DATOS (los arrays JS de plantilla/index.html)

### 4.1 days[]  (7 días)
```
{ short:"Lun", full:"Lunes",
  sport:"⚽ Entreno 19h",        // emoji + tipo de sesión
  sportClass:"run",              // run | fuerza | crossfit | rest
  sportBanner:"Descripción de la sesión y cómo afecta a las comidas",
  suppl:null,                    // null o string con \n (recordatorio de suplementación)
  libre:false,                   // true → banner de cena libre
  meals:[ { type:"C", time:"14:00", name:"Comida", tags:[], desc:"Línea 1\nLínea 2",
            short:"Resumen corto", note:"Adaptación o consejo", libre:false } ],
  batchCooking:null }            // opcional: { title, items[], note } (domingo)
```
Tipos de comida: D Desayuno · A Almuerzo (media mañana) · C Comida (mediodía) ·
Me Merienda · Ce Cena. COMIDAS POR DEFECTO: D, A, C, Me, Ce. Quitar las que el
cliente no haga (A y D son opcionales según cliente) y ajustar la leyenda.
No confundir nunca A con C.

- `desc`: cada `\n` crea una pill de ingrediente. Cantidades en gramos.
- `short`: resumen de 2-5 palabras que se muestra en la tabla semanal. Si falta,
  se usa `name`.
- `tags`: [] | ["extra"] | ["batch"].
- Una comida libre lleva `libre:true` y se pinta como "Libre".

### 4.2 Tabla semanal
La tabla NO se escribe a mano: `buildSummary()` la genera desde `days[]` usando
`short`. Solo aparecen las filas de las comidas que algún día tiene el cliente.
Un día sin esa comida muestra "—". Al cambiar una comida: actualizar `short`,
`desc`, `note` Y la lista de compra.

### 4.3 shopCategories[]
Cuatro categorías fijas: 🫘 Proteínas (cat-prot) · 🌾 Carbohidratos (cat-carb) ·
🥑 Grasas (cat-fat) · 🧄 Extras (cat-extra). Cada ítem: { name, qty }.

### 4.4 recetas[]
{ emoji, nombre, tiempo, raciones, utensilios, ingredientes[], pasos[], tip }.
La plantilla trae una receta de relleno ("Receta por definir"): sustituirla o, si el
cliente no tiene recetas, quitar el array y el bloque HTML de Recetas.

### 4.5 Regla de JavaScript
UN único <script> al final del body. Las funciones (badgeClass, render, buildTabs,
buildSummary, renderShop, buildShopTabs, buildRecetas, toggleReceta) no se modifican
por cliente; solo cambian los arrays. Llamadas finales, en este orden:
buildTabs(); render(); buildSummary(); buildShopTabs(); renderShop(); buildRecetas();

## 5. CLAUDE.md DE CADA CLIENTE

Se crea desde plantilla/CLAUDE.md. Contiene: estado, idioma, archivos, estructura,
estilo, contexto del cliente, PERFIL MÁSTER (descripción, hábitos, aversiones,
valoración, antropometría, bioimpedancia, somatotipo, próxima revisión), criterios
nutricionales, privacidad y reglas de trabajo. Es la fuente de verdad del cliente.

Privacidad: los repos de cliente son públicos (GitHub Pages) y CLAUDE.md también.
Lo que Guille decida que va ahí es público. Analíticas, hallazgos fuera del ámbito
nutricional y notas sensibles viven fuera del repo salvo decisión expresa.

## 6. PROCESO PARA UN CLIENTE NUEVO

1. Crear un repo VACÍO `nombreapellido` (manual en GitHub, p. ej. público si va a
   Pages) y darle acceso a la sesión de Claude. Claude no puede crear repos (403).
2. Dar a Claude: nombre completo, objetivo y contexto conocido.
3. Claude clona el repo vacío del cliente, copia plantilla/ del repo maestro (con
   Logo.png), sustituye los marcadores {{...}}, añade una copia de esta guía y hace
   push a main (git, un solo commit inicial).
4. (Alternativa si no se puede clonar: Claude sube los archivos de texto con las
   herramientas de GitHub y el Logo.png se sube a mano arrastrándolo al repo.)
5. Activar GitHub Pages en el repo (Settings → Pages → rama main).
6. Probar: `node --check` del <script>, escritorio y móvil (~430 px), impresión.
7. Tras la consulta: rellenar perfil máster, days[], shopCategories[] y recetas[].
   Mientras no haya datos, todo "Por definir" y comentario de borrador en el HTML.

Marcadores de la plantilla
  index.html : {{NOMBRE_CLIENTE}} {{SUBTITULO}} {{OBJETIVO}} {{IMPRESION_TITULO}}
               {{IMPRESION_TEXTO}}
  CLAUDE.md  : {{NOMBRE_CLIENTE}} {{REPO}} {{CONTEXTO_CLIENTE}} {{OBJETIVO_CLIENTE}}
               {{FECHA_CONSULTA}}

## 7. BLOQUES OPCIONALES

### 7.1 Suplementación (solo si aplica; tras la lista de compra)
```html
<div style="margin-top:2.5rem;">
  <div class="section-label">Suplementación recomendada</div>
  <div class="pn-supl-block">
    <div class="pn-supl-item"><div class="pn-supl-dot"></div>
      <div><strong>[SUPLEMENTO]</strong> — [DOSIS, FRECUENCIA Y JUSTIFICACIÓN]</div></div>
  </div>
</div>
```

### 7.2 Sección personalizada (solo si aplica; tras Recetas)
Para contexto específico: calendario de competición, hidratación deportiva,
protocolo de recuperación, fases nutricionales, etc. Mismo patrón de sección
(margin-top:2.5rem + section-label descriptivo) y tarjetas con borde var(--bdm),
radio 12px. Iconos de estado, con colores de la app:
  ✅ completado        → fondo var(--t50)      borde var(--t100)
  🔵 próximo / en curso → fondo var(--gold-50)  borde var(--pill-au)
  ⬜ pendiente          → fondo var(--g100)     borde var(--g200)
  ❌ no logrado (con criterio) → fondo #fdf0f0  borde #f4b8b8
Cada ítem: <div style="display:flex;align-items:center;gap:10px;padding:6px 10px;
background:[fondo];border:1px solid [borde];border-radius:8px;"> icono (18px) +
título (13px, 500) + detalle (12px, var(--g400)).
